# TorBridge 1.2.15 - phone-to-phone setup

Android can now show a setup QR as well as scan one. Copy connections and
download preferences from a configured phone to another phone on the same
Wi-Fi without a desktop or manually copying credentials.

## Changes

- Add **Show setup QR** on Android and rename the receiver to **Scan setup QR**.
- Adapt instructions and connection errors for phone or desktop senders.
- Make pairing dialogs scrollable on small screens and fix a settings dropdown
  overflow. Explain that the QR grants access to the setup.
- Prevent cleanup from an old transfer cancelling a newly opened QR session.
- Preserve encrypted single-use transfer, five-minute expiry, verification
  codes and explicit import confirmation. No downloaded files are transferred
  or deleted; the sender's configuration is unchanged.

## Install and use

Install the ARM64 APK over TorBridge on **both** the S25 and Pixel 7a. Do not
uninstall or clear storage. Version 1.2.15 uses Android code 18, the existing
application ID `app.torbridge.torbridge` and signing certificate. The universal
APK supports the other included Android architectures. For Windows, extract
the complete ZIP and keep its dependencies together.

On the S25: **Settings > Transfer setup > Show setup QR**.
On the Pixel: **Settings > Transfer setup > Scan setup QR**. Allow camera
access, compare the displayed codes and tap **Import setup**. Keep both phones
unlocked on the same Wi-Fi and leave the sender's QR screen open. Import
replaces the receiving phone's connections and download rules. Run Diagnostics
afterward. Local watched history and downloaded files are not copied.

If pairing cannot connect, check guest-network isolation or VPN restrictions.
If a QR was already claimed or expired, close and reopen the sender dialog.
This release does not change download resume behavior or establish that the
Pixel's earlier DNS/interruption problem is resolved.

## Validation

- Flutter analysis is clean and all **118 host tests** pass, including Android
  and Windows setup controls at 360 x 640 with 1.4x text scaling, encrypted
  round-trip, single use, tampering, expiry and replacement-session regressions.
- The **Android API 36 emulator** successfully offered setup on its actual
  local address and redeemed it through an independent service instance.
- Both APKs passed signature, existing-certificate, package/version and ABI
  checks. The universal APK installed over the emulator app and launched.
  ARM64 contents were checked structurally, not run on a physical ARM64 phone.
- All **32 Windows ZIP entries** match the release build. EXE and bundle
  metadata report 1.2.15+18. Release-tool fixtures pass.
- SHA-256 checksums accompany the binaries. Uploaded assets are downloaded
  again and compared with local hashes before publication.

See the [design and failure-case review](../phone-setup-transfer.md).

Physical S25-to-Pixel camera scanning and Android 17 were not available for
testing. The Android socket test uses synthetic credentials on an API 36
emulator; it does not prove two physical devices can communicate on a particular
Wi-Fi or VPN configuration.
