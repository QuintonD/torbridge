# TorBridge 1.2.13 — network diagnostics and safe recovery

This update addresses confirmed application problems exposed by the Pixel
download failures. The reported TorBox hostname lookup failure is confirmed;
its underlying network cause and the original Android interruption remain
unresolved. Reinstalling from scratch is not required.

## Changes

- Pause pending work after DNS, connection, or link-preparation timeout failures.
  Save waiting records and offer **Resume waiting downloads** with fresh links.
- Preserve failed Android native IDs and files while preparing replacement
  links. Retire the old transfer only after link preparation and storage preflight
  succeed, and keep the record if retirement fails.
- Run actual DNS and HTTPS service checks in Diagnostics. Distinguish failed
  name resolution, rejected authorization, TLS, timeout, and HTTP errors.
- Show Android API level, active network validation, VPN presence, Private DNS
  mode, and check time. Configured credentials alone no longer imply access.
- Show safe request-host and stage messages instead of raw Dio errors; sanitize
  saved legacy DNS failures without clearing settings or download records.
- Correct the Android/server HTTP 400 label and empty-library protection result.
  Handle immediate resume and restored-transfer queue races.

The Windows ZIP contains the shared recovery and diagnostics changes. Existing
native transfers can continue while pending work waits for the network.

## Updating

Install the ARM64 APK over TorBridge on Pixel 7a, Galaxy S25, and other supported
ARM64 phones. A universal APK is available for other supported Android ABIs.
Both APKs use application ID `app.torbridge.torbridge`, version **1.2.13**, code
**16**, and the existing signing certificate. Do not uninstall or clear app
storage. An APK is both the installer and update file.

On Windows, extract the complete ZIP into a new folder and launch `torbridge.exe`
with all included DLLs and the data folder. Existing user settings are preserved.

Run **Diagnostics → Run checks** after updating. If DNS or service access fails,
compare the phones close together and compare the Pixel on another network.
Tailscale without an exit node can still affect DNS depending on configuration;
its role in this report has not been established. Once service checks pass,
choose **Downloads → Resume waiting downloads** and confirm playback. Reopen
TorBridge to advance its serial queue if Android closes the app.

## Validation and limitations

- Flutter analysis is clean; all **101 host tests** pass.
- All **six Android API 36 emulator integration tests** pass. They cover the
  network channel and failed system DNS lookup, local-policy and server HTTP
  400, interrupted-response 1008 recovery, storage preflight, retained files,
  byte ranges, and completion without Flutter polling.
- No physical Pixel 7a, Galaxy S25, Android 17 device, or authenticated provider
  download was tested. Fixtures do not establish multi-gigabyte transfer behavior.
- DNS and API checks describe that moment. A passing API check does not validate
  the media CDN or guarantee a full download. The app does not change DNS/VPN
  settings or automatically repair a failing network.

See the [diagnosis, patch review, and comparison steps](https://github.com/QuintonD/torbridge/blob/main/docs/pixel-network-diagnosis.md).
