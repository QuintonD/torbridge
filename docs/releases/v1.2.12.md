# TorBridge 1.2.12 — download queue and recovery

This update fixes confirmed application gaps found while investigating repeated
Pixel 7a download failures. It preserves settings, saved records, and the offline
library. It cannot guarantee that a failing provider or interrupted connection
will recover.

## Changes

- Recover HTTP 400 through a bounded source-refresh/TorBox fallback sequence.
- Recover restored Android transfers after loading saved credentials.
- Start one new Android transfer at a time, including recovery of older failed
  batches. Save waiting items and allow cancellation without starting them.
- Refresh queued sources when their turn arrives, check available destination
  storage against the estimated file size, and keep 512 MiB of headroom.
- Stop on storage errors, preserving the failed record and native ID. Show free
  download storage in Diagnostics and clearer errors with request hostnames.
- Bound recovery link preparation and keep addon headers off direct TorBox links.

The Windows ZIP includes the shared controller and error-handling changes.
Windows keeps its existing concurrent transfer behavior.

## Install over the existing app

- Pixel 7a / ARM64: `TorBridge-Android-1.2.12-arm64.apk`.
- Other supported Android architectures: `TorBridge-Android-1.2.12.apk`.
- Windows x64: extract the entire `TorBridge-Windows-x64-1.2.12.zip` and launch
  `torbridge.exe` with the included DLLs and data folder.

Both APKs use application ID `app.torbridge.torbridge`, version 1.2.12, code 15,
and the existing signing certificate. **Do not uninstall or clear app storage.**
The APK is both the installer and update file.

After updating, run Diagnostics and retry one failed video, then check playback
before retrying a batch. New Android transfers run one at a time. An active
transfer can continue in Android, but **reopen TorBridge to start the next queued
item if Android closes the app**. Existing native transfers are preserved.

## Validation and limitations

- Flutter analysis: clean; 88 host tests pass.
- Android API 36 emulator: four native integration tests pass, including real
  HTTP 400, interrupted-response 1008, storage preflight, deletion/re-download,
  file/content byte ranges, and background completion retention.
- The universal release APK installed over 1.2.11 on the API 36 emulator,
  preserved a test file in private app storage, and launched successfully.
- Both APK signatures, app/version metadata, and ABI contents were verified.
  ARM64 contains only `arm64-v8a`; universal also includes `armeabi-v7a` and
  `x86_64`. All 32 Windows ZIP entries match their release build bytes; the
  executable and bundled version label report 1.2.12+15.
- Physical Pixel 7a / Android 17 and authenticated provider downloads were not
  tested. Fixtures do not establish multi-gigabyte network or capacity behavior.
- Storage sizes are estimates; the preflight does not reserve disk space. The
  screenshot's temporary-system storage has not been attributed to this app.

See the [investigation](https://github.com/QuintonD/torbridge/blob/main/docs/android-download-batches.md)
for confirmed bugs, queue behavior, and remaining uncertainty.
