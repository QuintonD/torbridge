# TorBridge 1.2.14 - file audits and durable download preparation

This update fixes defects confirmed with synthetic files and interrupted local
HTTP transfers. It does not establish the cause of the Pixel's original network
interruption. No reset or uninstall is required.

## Changes

- Save all selected episode intents before looking up sources. A failed lookup
  no longer loses the batch or leaves the app busy. Prepare sources when each
  job starts, and never reuse an old URL after a timed-out refresh.
- Back off application recovery after DNS, connection and timeout failures.
  Keep the schedule across restarts, limit automatic attempts to five, and
  respect HTTP 429 cooldowns. Keep TorBridge open for application retries.
- Preserve Android's existing paused transfers. Recover an enqueue interrupted
  before its native ID was saved; stop uncertain new work when ownership cannot
  be established safely.
- Add a read-only inventory of managed files, native records and retention
  mappings. Report active partials, failed partials, untracked files, missing
  files, stale mappings, duplicate references, empty attempt directories and
  incomplete scans. Nothing is automatically cleaned up.
- Reject empty/tiny files and obvious HTML/JSON error payloads returned as
  HTTP 200. Retain completion byte counts so later truncation is detectable.
  Preserve suspicious bytes and keep the download record available for review.
- Show received bytes, last byte progress, waiting-work storage estimates and
  unknown sizes in Diagnostics. Limit Windows transfers to two concurrent jobs.

## Updating and checking the Pixel

Install the ARM64 APK over TorBridge on Pixel 7a or Galaxy S25. The universal
APK supports the other included Android architectures. Both use application ID
`app.torbridge.torbridge`, version **1.2.14**, Android code **17**, and the existing
signing certificate. Do not uninstall or clear app storage.

For Windows, extract the complete ZIP into a new folder and run `torbridge.exe`
with its DLLs and data folder. Existing settings remain in user storage.

Open **Diagnostics > Run checks**. Review the file audit and actual DNS/service
checks. Once connectivity works, use **Resume waiting downloads** or retry an
individual failed item. Start with one small download and verify playback before
adding a large queue. Untracked files are reported, not silently removed.

## What the checks can and cannot prove

Header and recorded-size checks detect specific defects; they are not a full
video decode or provider-authenticated hash. An unsupported container, unknown
length, inaccessible content URI or incomplete scan remains explicitly
unverified. Audit categories can overlap, such as an untracked suspicious file.

Android can continue active transfers outside the app. Preparing the next queued
job and application-level recovery still require TorBridge open. A separate
background writer was not added without a safe transactional ownership design.
A terminal resume failure may restart from zero with a fresh link. Bytes from
different sources are never intentionally joined.

The Pixel 7a, Galaxy S25, Android 17, weak Wi-Fi/roaming, physical reboot endurance,
and authenticated multi-GB TorBox queues were not available for direct testing.
The Pixel's failed TorBox DNS lookup is confirmed by its screenshots; Tailscale's
role and the cause of the original interruption remain hypotheses.

## Validation

- Flutter analysis is clean; all **114 host tests** pass. Regressions include a
  1,000-intent queue, stale-link refusal, bounded retry schedules, overlapping
  rate limits, failed persistence, enqueue-gap reconciliation, and read-only
  inventory/integrity checks.
- All **ten Android API 36 emulator tests** pass. They cover real system DNS
  failure, HTTP 400/1008 recovery, retained files and range serving, completion
  without Flutter polling, HTTP 200 error-page rejection, ignored ranges,
  changed validators, byte-identical resume and retained-file truncation.
- Both release APKs passed signature, existing-certificate, package/version and
  ABI checks. The universal APK installed over published 1.2.13 on the API 36
  emulator, preserved a private-data fixture byte-for-byte, and launched.
  ARM64 was checked structurally; this x86_64 emulator does not validate it on
  a physical ARM64 phone.
- All 32 Windows ZIP entries match the release build; EXE and bundle versions
  match 1.2.14+17. Release-tool fixtures pass. The ZIP includes all dependencies.
- SHA-256 checksums accompany the binaries. Uploaded assets are downloaded and
  checked against the local artifacts before the release is made public.

See the [validated plan and implementation review](../download-integrity-and-queue-plan.md).
