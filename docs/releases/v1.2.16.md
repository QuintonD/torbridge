# TorBridge Android 1.2.16 - stop silent download restarts

Interrupted downloads that Android cannot resume now stop with an explanation
instead of repeatedly starting replacement transfers from zero. Ordinary
Android retries and byte-range resumption continue when supported by the server.

## Changes

- Stop automatic source replacement for Android cannot-resume failures (1008)
  and terminal failures after observed byte progress, including rate limits.
- Keep the failed download record and native identity for inspection. Record
  the failure reason, reported host and observed bytes without signed URLs.
- Keep observed progress if the final failed platform snapshot loses counters.
- Explain that explicit Retry starts a new transfer from zero. Android may
  already have removed unusable partial bytes; this update cannot recover them.
- Add network transport, metering, Data Saver, Battery Saver, battery exemption
  and background restriction to Android Diagnostics.

## Install

Install the ARM64 APK over the existing app on Pixel 7a or Galaxy S25. Do not
uninstall or clear app storage. The universal APK supports other included Android
architectures. Application ID and signing certificate are preserved. Both APKs
use version 1.2.16 / Android version code 19.

Windows remains on 1.2.15; this release changes the Android download path.

## Validation and limitations

- Local Flutter analysis passed; all 126 host tests passed.
- Six download recovery and four download integrity integration tests passed
  on an Android 16 / API 36 emulator. Stable ETag/range recovery retained the
  native job ID and produced byte-identical output.
- GitHub CI skipped at the user's request. Existing local test results cover
  the implementation; the release version and notes were subsequently updated.
- APK signatures, certificate continuity, package/version metadata, native ABIs
  and uploaded asset SHA-256 checksums are verified during release preparation.
- No physical Pixel 7a, Galaxy S25 or API 37 device was tested. The user reports
  the Pixel succeeds on 4G, making its original Wi-Fi path a stronger suspect.
  This release stops silent replacement attempts; it does not fix weak Wi-Fi,
  guarantee continuation after a server rejects resume, or promise that all
  temporary storage is cleaned up. Failed/untracked files are preserved for
  inspection rather than indiscriminately deleted.

See [the investigation](../pixel-download-restarts.md). SHA256SUMS.txt accompanies
the APKs.
